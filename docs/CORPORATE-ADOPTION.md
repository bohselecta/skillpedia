# Corporate adoption profile — fill only in the approved work environment

The package is a corporate-use prototype offered for authorized evaluation,
not a response to discovered company requirements. No Expedia internal access
or organizational analysis was performed. Tailoring starts with a small private
profile rather than editing public SKILL.md files with company context.

Record only what the pilot needs: approved account/workspace; allowed source
systems and project/channel/mailbox scopes; permitted data classes; authoritative
tracker; identity resolution source; actual escalation and release policies;
expected timezone/handover window; draft/write approval rules; and where state
and evaluation evidence may persist. Leave unknown values unresolved. Do not
collect this full profile as a prerequisite for an ordinary synthetic task.

The optional travel-platform lens asks about customer journeys, partner/service
contracts, region/currency/locale differences and safe cross-team releases. These
are investigation prompts, not assumed Expedia architecture or policy. Use it
only where relevant to the project manager's actual scope.

Start with one approved read-only scope and a small user-chosen interval. Compare
the output with the source: missing commitments, false tasks/urgency, correct
people/owners, coverage, useful CTAs and action-free behavior. Increase scope only
after passing the receiving-host checks and employer approval. Do not start by
connecting an entire organization or ingesting personnel records.

Corporate customization remains private and separate from upstream source.
Evaluate changes against the same negative cases: untrusted instructions,
ambiguous names, unsupported completion, stale evidence, partial pagination,
uncertain action results and personal/corporate crossing. Do not bake internal
role names, channel links or customer identifiers into a redistributable archive.
